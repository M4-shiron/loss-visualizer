## 段階1: プロジェクト雛形と画面骨格（2026-08-29）

### 実施した変更

- 技術スタックを決定し、プロジェクト雛形を作成した。
  - Vite 8 + React 19 + TypeScript 6（完全クライアント動作のため、SSRを持つ構成は採らない）
  - Tailwind CSS 4（`@tailwindcss/vite` プラグイン。設定ファイル不要）
  - React Router 7（スマートフォンの「戻る」操作を自然に動かすため）
  - Vitest 4 + Testing Library（単体・結合テスト）
  - oxlint（雛形に同梱。静的解析）
- `.gitignore` にWeb開発用の除外（`.vite/`、`coverage/`、`*.local`、`.vercel`）を追記した。
- Gitリポジトリを初期化し、初回コミットを作成した。
- 画面骨格を6ルートで作成した。中身はすべて仮表示で、担当ループ番号を画面上に明示している。

  | パス | 画面 | ナビ | 実装予定 |
  |---|---|---|---|
  | `/` | ホーム | あり | 第4ループ |
  | `/decide` | 購入判断フロー | なし（操作に集中させる） | 第3ループ |
  | `/history` | 履歴 | あり | 第5ループ |
  | `/pending` | 保留 | あり | 第5ループ |
  | `/settings` | 設定 | あり | 第4・6ループ |
  | `/onboarding` | 初回設定 | なし | 第4ループ |

- モバイルファーストのレイアウト土台を作成した。
  - 最大幅 `max-w-md` の中央寄せ（大きな画面でも間延びさせない）
  - 下部固定ナビ。`env(safe-area-inset-bottom)` でiPhoneのホームバーを避ける
  - `viewport-fit=cover`、タップハイライト無効化、iOS Safariの入力時自動ズーム防止
- ホームに購入判断への大きな導線（最小高さ112px）を配置した。仕様12の「最優先要素」に対応する。

### 実行した検証と結果

- 型チェック（`npm run typecheck` / `tsc -b`）: エラー0件
- 静的解析（`npm run lint` / oxlint）: 指摘0件、終了コード0
- 本番ビルド（`npm run build`）: 成功、警告0件。出力 JS 238.27 kB（gzip 76.48 kB）、CSS 15.50 kB（gzip 3.75 kB）
- 単体・結合テスト（`npm test` / Vitest）: 1ファイル7件すべて成功
  - ホームに購入判断への導線が表示される
  - ホームの導線から購入判断画面へ移動できる
  - 下部ナビから履歴・保留・設定へ移動できる（3件）
  - 初回設定の画面を開ける
  - 未定義パスがホームへリダイレクトされる
- 開発サーバー（`npm run dev`）: 起動成功。Local `http://localhost:5173/`、Network `http://172.20.10.3:5173/`
- ブラウザ実表示確認（Chrome / 幅375px）: 全6ルート＋未定義パスで横スクロールなし（`scrollWidth 375 = clientWidth 375`）。ナビの表示・非表示が設計どおり
- ブラウザのコンソール: エラー・警告0件（Viteの接続ログとReact DevTools案内のみ）

### 発見した問題と原因

- Chromeウィンドウが最大化状態でリサイズAPIが効かず、ウィンドウ幅でのスマートフォン表示確認ができなかった。375px幅のiframeにアプリを読み込む方法で、実際のビューポート幅375pxとしてレイアウトを検証した。

### 残存リスクと未解決事項

- **静的ホスティングのSPAフォールバック未設定**: 現状 `/decide` などへ直接アクセスすると、本番配信時に404になる。Vercelへ公開する段階で `vercel.json` にリライト設定が必要。開発サーバーと `vite preview` では問題が出ないため、公開ループまで顕在化しない。
- **実機iPhoneでの表示・操作感は未確認**: PC上のChromeでの375px検証のみ。同一Wi-Fi内から `http://172.20.10.3:5173/` で確認できる状態にはしてある（IPアドレスはネットワーク環境で変わる）。
- **通知（仕様16）はWebでは仕様どおり実装できない**: アプリを閉じている間の時刻指定通知はWebに存在せず、バックエンドなしの制約とも両立しない。段階6までに方針決定が必要（推奨はアプリ内通知への置き換え）。保留の24時間経過処理そのものは通知と無関係に実装可能。
- **ダークモード未対応**: 仕様に要求がないため実装していない。必要なら段階6で判断する。
