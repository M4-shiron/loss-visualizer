## 段階3: 購入判断フロー（2026-08-29）

### 実施した変更

- `seed/general_comparisons.json` の61件全てに助数詞 `unit`（個／回／本／杯／袋／枚／足／着／台／か月／セット／冊）を追加した。既存の意味・価格は変更していない。表示文はseedに固定せず、比較ロジック側で組み立てる（今回の指示どおり）。
- 比較カード選択ロジック（`src/domain/comparison.ts`, `comparisonCard.ts`）を実装。
  - 優先順位は §7 のとおり ①価値尺度 ②節約目標 ③一般比較。
  - **カード合計は3枚を上限**とした（当初計画の4枚から、購入直前の画面での情報過多を避けるためユーザー指示で調整）。価値尺度・目標が両方ある場合は一般比較を1枚に絞る。一般比較単体の上限2枚（§8）は独立して維持。
  - 一般比較は `|log(amount/price)|` が最小の順に選び、2枚目は1枚目と異なるカテゴリを優先。
  - 価値尺度・目標が未登録でも、一般比較のみでカードが最低1枚成立する。
- 状態管理層（`src/store/`）を新設。`AppStateProvider` が起動時にlocalStorageから読み込み、`recordDecision` で判断を記録するたびに保存する。Fast Refresh警告を避けるため、Context定義・Provider・hookを3ファイルに分割した（`context.ts` / `AppStateContext.tsx` / `useAppState.ts`）。
- `DecideScreen` を実装。仕様どおり画面を増やさず、入力→判断→（買うのみ）理由選択→結果の4内部ステップとして1画面に収めた。
  - 入力: カテゴリ8択、金額（OSの数字キーパッド、最大9,999,999円）、商品名（任意）。
  - 判断: 金額表示、カテゴリ別の問いかけ（ランダム1件、ステップ突入時に1回だけ抽選）、比較カード、画面下部固定の3択ボタン。
  - 買うを選んだ場合のみ理由選択ステップ（5択＋スキップ）を挟む。
  - 結果: やめる＝達成演出＋優先目標のゲージ更新、買う＝中立トーン＋選んだ理由、あとで考える＝保留の説明。実績を解除した場合はその場で表示。
  - 途中の「戻る」は判断・理由選択ステップから前段へ戻るのみで、記録は行わない。結果ステップに達したら戻れない。
- 達成演出はJSタイミング制御（カウントアップ・setTimeoutでのゲージアニメーション）を避け、CSSキーフレーム1つ（`animate-pop-in`）と静的な進捗バーで表現した。テストの安定性を優先した簡略化であり、意図的な設計判断として記録する。

### `/code-review medium` の指摘と対応

1. **`recordDecision` が非関数型の `setData` で古い `data` を参照しており、再描画前に連続で呼ばれると1件目の記録が上書きで消える可能性があった。** → 保存する `setData` を関数型（`prev => ...`)に変更し、常に直前の実データを基準にマージするよう修正。加えて `DecideScreen` 側に `useRef` による二重送信ガードを追加し、同一マウント中は `finalizeDecision` が一度しか実行されないようにした。**ガードを一時的に外して同一 `act()` 内で2連続タップを再現するテストが実際に失敗することを確認してから、ガードを復元・コミット**（テストが本当にバグを検知することを検証済み）。
2. **価値尺度カードの「あと4回見送れば◯◯に届きます」という文言が、判断前の画面なのに「今回やめる」ことを前提にした書き方になっていた。** → 「今回を含めて{N}回、同じ判断をすれば◯◯に届きます」に変更し、まだ選んでいない今回の判断を前提にしない中立的な表現にした。
